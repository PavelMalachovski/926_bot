## Правила

**R1. D1-фильтр.** D1-range = high/low последних 20 закрытых D1-баров.
pos = (entry − low) / (high − low).
BUY только при pos ≤ 45%, SELL только при pos ≥ 55%. Между 45–55% —
вход допустим только по тренду H4 и H1 одновременно. Против — «сетапа нет»
(PNG с разметкой всё равно), без исключений.

**R2. Entry на ближнем краю зоны** — первый край, который цена встретит на откате:
- OB: для BUY — верх тела OB, для SELL — низ тела OB;
- FVG: ближний край гэпа;
- OTE: уровень 62% (не 70.5%).
Затем упреждение 2 п в сторону цены (BUY: entry + 0.02, SELL: entry − 0.02).
Если два уровня (OB/FVG/OTE) пересекаются — край пересечения, ближний к цене.

**R3. Минимальный SL 22 п.** SL за swing/Strong High-Low + ~10 п буфера; если
вышло < 22 п — SL за следующий swing (не сужать). Риск > 50 п — «сетапа нет».

**R4. TP1 = ближайший незанятый пул, даже при RR 1.0–1.5.**
На TP1 фиксировать 50%, SL остатка → BE. Остаток — на TP2 (следующий пул).
RR < 1.0 к TP1 — «сетапа нет». Предупреждение «RR < 1:2» больше не ставится;
вместо него показывать RR к TP1 и к TP2 и «смешанный RR» = 0.5·RR1 + 0.5·RR2.

**R5. BE и новости.**
- SL → BE только после TP1 или хода ≥ 1.0R в пользу сделки (не по H1 close).
- pm-ордер — только если до ближайшей красной новости USD/JPY ≥ 2 ч от
  создания; вход, попадающий в 14:00–15:00 в день NFP/CPI/FOMC/BOJ, = «сетапа нет».
- Неисполненный лимит снимается за 60 мин до красной новости (блэкаут).

## Учёт результата в журнале (R4)

- TP1 взят раньше SL → status = "TP", result_r = 0.5·rr_tp1 + 0.5·(исход остатка):
  - остаток дошёл до TP2 → +0.5·rr_tp2;
  - остаток выбит в BE → 0;
  - к экспирации остаток открыт → закрыть по close последнего M5-бара (в R).
- SL раньше TP1 → "SL", result_r = −1.
- Поля новых записей: "rules": "v2", "tp2", "rr_tp2", "d1_pos" (%), "partial" (bool,
  TP1 взят), "runner_result_r".
- stats.json: блоки "v1" и "v2" считаются отдельно (те же поля, что общий счёт);
  общий счёт — как раньше по всем записям. В строке 📊 выводить общий счёт, а
